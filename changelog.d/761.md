### Added

- The weekly reset returns to the host schedule: `crew reset` drains a box to the store before the disk goes back to its `armed` checkpoint, and refuses a box it cannot drain (#761).
- The reset writes the member's memory — every ledger and state file the store holds — back onto the restored disk as one archive unpacked under the duty lock, so the first duty that runs reads the whole of it, and a write-back that fails is said by name (#761).
- Panels follow the head's risk: a pull request that touches no risky path and stays under `PANEL_RISK_MAX_FILES` and `PANEL_RISK_MAX_LINES` has a panel of `PANEL_LOW_RISK_SIZE`, rotated by number and fixed per head; anything else gets the whole roster (#761).
- The sized panel is the panel: the request goes to it and the handoff counts its approvals alone (#761).
- The panel's tier and what decided it are posted on the pull request once per head (#761).
- `crew hire --pool <name>` names the credential pool a member spends from, written into the box's instance.conf and kept across a re-install, so several members on one subscription are read as one pool by `crew usage --by pool` (#761).
- `crew status <box>` prints the observed peak memory from the store beside the role's `BOX_MEMORY`, the reading the size is set by (#761).
