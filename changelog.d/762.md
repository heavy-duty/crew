### Added

- The release cut: for every track in `RELEASE_TRACKS` (`owner/repo:path:tag-prefix[:hold]`), the triage member's tick reads the main clone and the board and decides the cut in shell, every refusal naming its reason on the record (#762).
- A cut is bought only when main carries merges for the track since its last tag with fragments waiting, VERSION armed, CI green at the head, main quiet, no release pull request open and the head not yet cut (#762).
- The `release` session stamps VERSION, assembles the changelog through ceremony's own `bin/changelog-assemble` at the consumer's pin, writes the track's drill record honestly — what the box exercised, what is owed to the approver — opens one pull request labelled `release`, and stops (#762).
- A cut main moved past on the track is withdrawn when every commit on it is the engine's, and never re-pushed; a cut a person closed stays refused for that track's tree, so an off-track merge re-opens nothing (#762).
- A session that opens no pull request is retried `RELEASE_MAX_TRIES` times and then refused, and a cut waiting for main's quiet window wakes the box from the host tick when due (#762).
- `examples/README.md` walks heavy-duty/la-familia-site's fleet definition as the worked example, and `shared/docs/release-cut.md` is the runbook from a ticket to a deployed version with the three doors a person opens (#762).

### Changed

- The ceremony pin is `0.7.11` everywhere in this tree (the doctrine mirror, the workflows, the prompts' vocabulary); the one prompt divergence against it, the retired `post-merge` queue label, was removed in wave 1 (#762, #757).
